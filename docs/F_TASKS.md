# F组正式队员题

## 共同要求

- 保留原有构建可用；提交修改、测试、简短设计说明和运行命令。
- 只修改所选题目涉及的模块，不要求大规模重写。
- 不能把公开样本文件名写成特殊分支；算法组会替换时间顺序、噪声或隐藏样本。
- 最低完成标准是“行为正确、故障可解释、程序不会崩溃”，不是追求复杂模型。
- 输入字段、单位、空帧表示和阈值以 [数据与行为契约](DATA_CONTRACTS.md) 为准。弱基线允许不满足目标行为；随仓库提供的检查不代表算法已通过验收。

## F1：多车遮挡下的灯条关联与装甲板完整性判断

**比赛情景**：两辆敌方车在哨兵视野中交错，前车底盘会挡住后车的一根灯条。旧程序把所有亮线直接配成装甲板，出现跨车配对和后车被遮挡时仍输出完整装甲板的问题。

**代码入口**：`src/f1_detector.hpp`、`src/f1_baseline.hpp`。

**输入**：`F1_lightbar_candidates.csv` 为多车候选，`F1_single_lightbar_candidates.csv` 为单车候选；两个 MP4 只用于回放和可视化。CSV 从公开视频中的可见彩色像素提取，候选人不需要写 BGR/HSV 分割、灯条检测器或视频读取器。视频按 30 fps 慢放，CSV 使用 60 Hz 仿真时间，须按帧号对应，不能直接用播放器秒数对应 CSV 秒数。

**要求**：

1. 实现 `ArmorAssociator::associate()`，从匿名灯条候选中给出左右配对。
2. 保留单车场景的基本配对能力，不能把不同车的灯条长期配成一个超宽装甲板。
3. 可见长度、方向等几何证据不足以支持完整配对时，输出 `complete=false`、低置信度或不配对；不能由单根灯条伪造完整装甲板。只按输入中可观察的证据评价，不要求从匿名几何恢复不可观察的遮挡真值。
4. 提供一个可运行的 CSV 回放程序或测试，输出 `frame,left_index,right_index,complete,confidence`。

**不要求**：重写图像检测、训练模型、实现四角点 PnP 或接入真实相机。

**验收**：分别回放单车和多车 CSV，并用自构造的已知配对、跨车歧义和部分可见样例验证行为。公开 CSV 没有配对真值，不能将配对数量当作准确率；严格误检率和跨车配对率由算法组用隐藏标签统计，公开报告需注明指标依据和无法判定的情况。

## F2：补齐跟踪器的丢失、重捕获和误检处理

**比赛情景**：目标被前车挡住约 1 秒，画面里仍有其他匿名候选；目标重新出现时位置已经变化。旧程序要么马上跳到误检，要么永久保持旧位置。

**代码入口**：`src/f2_tracker.hpp`、`src/f2_baseline.hpp`。

**输入**：`F2_observations.csv`。同一帧可能有多个匿名候选，不能依赖 `observation_id`；`measurement_valid=0` 的行只用于表示空帧，应调用 `update(timestamp, {})`。

**要求**：在已有 `BaselineReacquisitionTracker` 的基础上实现或修正 `Tracking -> TempLost -> Tracking/Lost` 状态过程。`REACQUIRED` 表示 `TempLost -> Tracking` 的事件，不是新增枚举值。短丢失期间允许有限预测；误检不能立即抢锁；重捕获后要更新位置和速度；长期没有目标必须释放轨迹。说明初始化、匹配门限和保持时长，连续没有有效匹配超过 2 秒时必须释放。

**不要求**：实现 Kalman/EKF、写检测器或接入相机。一个基于位置和时间戳的状态机即可完成题目。

**验收**：报告首次锁定帧、重捕获事件和最终释放帧，公开数据末尾包含 3 秒空帧。误检切换次数应在自构造的带标签测试中报告，公开数据只能报告有定义的关联变化代理指标，不能把 `candidate_0` 当成唯一正确目标。隐藏序列会改变误检位置和丢失窗口。

## F3：把多目标选择器改成带锁定滞回的目标管理

**比赛情景**：两辆敌车在准星附近交替占据更高分数，友军车距离更近，操作手中途指定目标。提供的基线已过滤友军，但每帧按最高 `threat` 重新选择，缺少锁定保持和切换滞回，准星容易横跳。

**代码入口**：`src/f3_target_manager.hpp`、`src/f3_baseline.hpp`；可增加独立纯函数测试，不要求接相机。

**输入**：`F3_target_snapshots.jsonl`。这是连续时间序列，不是互不相关的单题；其中包含短暂分数反超、持续反超、短时遮挡、友军竞争、有效/无效操作手指令和全目标过期阶段。

**最低行为契约**：在每帧重新选择的基线之上，先过滤友军、不可见和 `age_ms>200` 的目标；新目标 `threat` 至少高 0.1 且连续保持至少 500 ms 后才自动切换；当前目标短时丢失时进入 `TEMP_LOST` 并禁火；距最后有效可见时刻超过 1200 ms 才释放。合法操作手指令直接使用目标 ID 并立即覆盖自动选择，非法指令不能锁友军。`case` 只是场景说明，不能在切换场景时重置管理器。

**不要求**：修改检测或跟踪，也不要求神经网络。输入已经是目标快照，重点是状态、滞回和安全决策。

**验收**：统计切换次数、错误友军锁定、短反超造成的误切换、丢失后的释放时刻和重捕获时刻。输出必须带 `selected_id`、状态和原因。

## F4：修正弹道模块的边界和输入契约

**比赛情景**：弹速反馈偶尔为 0、NaN 或突然变化；目标在近距离、高低落差和最大射程附近出现。旧程序在无解时仍把旧角度发给云台。

**代码入口**：`src/f4_ballistic_solver.hpp`、`src/f4_baseline.hpp`。

**输入**：`F4_ballistic_cases.jsonl`。

**要求**：在已有无阻力低抛闭式解基线之上，明确处理无效距离、高度差、弹速、判别式无解和极端仰角。重力为 `9.80665 m/s²`，距离是水平距离，高度差向上为正；允许俯仰角为 `[-π/4, π/4]`，单位为弧度，飞行时间为秒；无解时返回 `valid=false` 和有限的零数值，由上层禁火。

**不要求**：建立完整空气阻力模型、接云台或改串口协议。可以只改这个纯函数和测试。

**验收**：公开案例和隐藏边界案例均不能输出 NaN/Inf；有效案例的水平距离与高度正向回代误差分别不超过 `1e-4 m`；无解案例不能沿用上一帧旧解。输入域和公式见数据契约。NaN/Inf 不写入标准 JSON，需通过 C++ 单元测试直接传入。

## F5：把端到端时延接入瞄准预测

**比赛情景**：相机、视觉处理、串口和弹丸飞行各有延迟。目标在高速横移，旧程序只加一个固定延时，命中点总是落在目标后方。

**代码入口**：`src/f5_latency_predictor.hpp`、`src/f5_baseline.hpp`。

**输入**：`F5_latency_sequence.csv`。

**要求**：在已有常速度基线之上，区分观测时刻、当前处理时刻和命中时刻。本题简化为处理完成即发送，额外串口/排队延迟为零；命中时刻为 `now_sec + flight_time_sec`。`processing_delay_sec` 是已发生的标称延迟，不能在观测年龄之外再重复补偿。速度估计属于观测时刻，不能使用未来真值；处理时延变化、历史不足、时间戳不连续和速度突变；输出预测时长、补偿后位置和 stale 状态。

**不要求**：实现相机线程、串口发送、弹丸模型或完整跟踪器。题目只考查时间语义和一个可测试的预测函数。

**验收**：必须给出零补偿、固定补偿和改进方案在同一带真值合成测试上的对照误差；可使用 `tests/f5_public_evaluation.py` 对公开 CSV 的回放结果评分。公开 CSV 不含真值列，离线评估器重建公开合成轨迹的命中位置；该真值不能传入预测器，公开合成误差也不等于实车误差或隐藏评分。隐藏序列会改变时延阶段和运动模式。

## F6：给运行时加上可复现的故障复盘能力

**比赛情景**：比赛中出现检测掉帧、时间戳倒退、跟踪状态没有清零却继续开火。只看最终“没打中”无法定位是感知、跟踪还是时序问题。

**代码入口**：`src/f6_replay_analyzer.hpp`、`src/f6_baseline.hpp`。

**程序输入（必需）**：`F6_detections.jsonl`、`F6_tracking.jsonl`、`F6_commands.jsonl`，恰好对应 `ReplayAnalyzer::analyze()` 的三个路径参数。

**人工核对资料（可选）**：`F6_public_issue_times.json` 是部分公开检查点，不是第四个程序输入，不是完整答案，也不能用它驱动分析器输出。`manual_review` 可以是正常对照点；精确帧号、时间单位和半开区间见数据契约。

**要求**：在已有 JSONL 基线检查器之上，以 `frame_id` 关联模块记录，同时按原始行序检查各模块时间戳；不能先按时间排序而抹掉倒退证据。识别检测缺失区间、乱序、目标 ID/状态与开火命令不一致、丢失期间继续开火等问题；至少新增一个可自动运行的复盘检查器或单元测试。仅凭检测缺行不能断言相机硬件掉帧，应报告证据及原因不确定性；`reason` 是待核查字段，不是答案。

**不要求**：设计新的日志格式、接入运行时系统或使用第三方大数据框架。候选人只需读取给定 JSONL 并输出结构化 `ReplayIssue`。

**验收**：`ReplayIssue.timestamp_sec` 必须是日志中的秒数，涉及模块、帧号和证据字段写入 `evidence`，安全影响写入 `safety_relevant`；同一日志重复运行结果及顺序必须一致，日志缺行不能导致程序崩溃。公开日志含可观察的 ID 不一致、丢失开火和时间倒退样例；也须自测缺失模块记录、空文件等边界。
